# Метрики успадкованого модуля SportEvents.Legacy («до» рефакторингу)

Спосіб вимірювання: ручний підрахунок за правилами розділу 3.5 методичних вказівок (LOC — значущі рядки без порожніх та коментарів; цикломатична складність $CC = 1 + \text{кількість точок розгалуження}$; глибина вкладеності — максимальна кількість вкладених блоків усередині методу).

## 1. Розрахунок цикломатичної складності методу `Handle`

| Точка розгалуження в методі `Handle` | Кількість |
| :--- | :--- |
| `if (items != null)` | 1 |
| `if (items.Count > 0)` | 1 |
| `if (state == "new" || state == "draft")` (оператор `if` + оператор `\|\|`) | 2 |
| `if (clientMail != null && clientMail.Contains("@"))` (оператор `if` + оператор `&&`) | 2 |
| Два цикли `for` (обчислення суми та форматування позицій звіту) | 2 |
| Три перевірки категорії учасника (`if` / `else if` / `else if`) | 3 |
| Три перевірки порогу знижки `if (sum > 500m)` | 3 |
| `if (afterDisc < 1000m)` + тернарний оператор `urgent ? 150m : 50m` | 2 |
| `if (sendMail)` | 1 |
| **Разом точок розгалуження** | **17** |

Підсумкова цикломатична складність методу `Handle`: $CC = 1 + 17 = 18$ (понад утричі перевищує рекомендований поріг курсу $CC \le 5$).

## 3. Додаткові структурні показники модуля («до»)

- **Кількість відповідальностей класу (6):** валідація вхідних даних, обчислення підсумку та шкали знижок, розрахунок вартості доставки, побудова багаторядкового тексту звіту, ведення внутрішнього журналу операцій, форматування опису учасника (`DescribeClient`).
- **Кількість дубльованих рядків між `Handle` і `Preview`:** 28 рядків (розрахунок суми позицій, трирівнева шкала знижок, обчислення доставки та форматування блоку звіту).
- **Кількість магічних чисел:** 7 унікальних літералів (`500m`, `0.15m`, `0.10m`, `0.12m`, `0.05m`, `0.07m`, `1000m`, `150m`, `50m` — разом 12 входжень у коді).
