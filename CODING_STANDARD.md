# Стандарт кодування навчального проєкту SportEvents

## 1. Загальні положення
Цей стандарт визначає обов'язкові правила іменування, форматування та оформлення вихідного коду для навчального проєкту **SportEvents** (варіант № 20: Реєстрація учасників і результати змагань). Мета стандарту — забезпечення високої читабельності коду та уникнення стилістичних конфліктів у командній розробці.

## 2. Іменування
Усі імена в проєкті мають бути англомовними, чіткими та відображати бізнес-суть.

| Сутність | Конвенція | Приклад | Антиприклад |
| :--- | :--- | :--- | :--- |
| Клас, запис | PascalCase, іменник | `RegistrationItem` | `registration_item` |
| Інтерфейс | I + PascalCase | `IRegistrationRepository` | `Repository` |
| Метод | PascalCase, дієслово | `CalculateTotal` | `calculate_total` |
| Властивість | PascalCase, іменник | `UnitPrice` | `getUnitPrice` |
| Приватне поле | camelCase з підкресленням | `_items` | `m_items` |
| Локальна змінна | camelCase | `totalAmount` | `Total_Amount` |
| Константа | PascalCase | `MaxParticipantsLimit` | `MAX_LIMIT` |
| Перелічення | PascalCase, однина | `RegistrationStatus` | `RegistrationStatuses` |

## 3. Форматування
1. **Відступ:** Рівно 4 пробіли; табуляція (`Tab`) заборонена.
2. **Довжина рядка:** Не більше ніж 100 символів на один рядок.
3. **Фігурні дужки:** Використовується стиль Allman (відкривна дужка завжди ставиться на новому рядку). Дужки є обов'язковими навіть для однієї інструкції в тілі `if` чи `foreach`.
4. **Порожні рядки:** Між членами класу має бути рівно один порожній рядок.
5. **Директиви using:** Розміщуються на початку файлу, системні простори імен ідуть першими, невикористані директиви видаляються.
6. **Простір імен:** Використовується сучасний стиль простору імен файлового рівня (`namespace SportEvents.Core.Domain;`).

## 4. Коментарі та документація
Коментарі мають пояснювати «чому» приймається певне технічне рішення, а не дублювати очевидний код («що» він робить).

* **Погано (дублювання коду):**
  ```csharp
  // збільшуємо лічильник позицій на одиницю
  count = count + 1;

* **Добре (пояснення логіки):**
  ```csharp
  // пропускаємо неактивних учасників, оскільки їхні ліцензії анульовані
  if (!participant.IsLicensed) continue;

## 5. Структура проєкту
Проєкт розділено на два модулі:
* **SportEvents.Core** — бібліотека класів із чистою бізнес-логікою та доменною моделлю.
* **SportEvents.App** — консольний застосунок для взаємодії з користувачем та виводу результатів.

## 6. Правила комітів
Повідомлення комітів пишуться за конвенцією *Conventional Commits*:
* `feat:` — додавання нової можливості (наприклад, моделі чи методу).
* `fix:` — виправлення помилки.
* `docs:` — оновлення документації або README.
* `chore:` — інфраструктурні зміни, конфігурації (`.editorconfig`, аналізатори).
